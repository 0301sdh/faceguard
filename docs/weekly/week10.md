# Week 10 — Spring Boot 백엔드 연결

> **결론:** Spring Boot 백엔드(`backend/`)를 만들어 AI 서버와 연결했다. 사진 올리기 → 보호 작업 → 보호된 사진 내려받기가 처음부터 끝까지 동작한다(Mac CPU 약 40초). 결과 사진은 AI 서버를 직접 불렀을 때와 바이트까지 같다. 오류 9가지도 정해 둔 응답이 나온다.

## 목표
사용자가 Spring Boot API를 호출하면 AI 서버가 사진을 처리하고, 결과를 저장·조회할 수 있게 한다.

## 핵심 개념
- **역할 나누기:** AI 서버(Python)는 노이즈만 만든다. 백엔드(Java)는 업로드 검증, 작업 기록, AI 서버 호출, 저장, 조회를 맡는다.
- **Spring Boot 구조:** Controller(요청 받기) → Service(일 처리) → Repository(DB 저장). Entity는 DB에 저장되는 기록의 모양이다.
- **DB에는 기록만:** 사진 파일은 폴더(`storage/images/`)에, DB에는 사진 정보와 파일 위치, 작업 상태만 둔다. 파일을 DB에 넣으면 무겁고 느려진다.
- **동기 방식:** 지금은 보호 작업을 만들면 AI 처리가 끝날 때까지 응답을 기다린다.

## 구성
| 위치 | 내용 |
|---|---|
| `image/` | 사진 올리기·검사·저장·내려받기. 파일 앞부분(매직 넘버)으로 진짜 JPEG/PNG/WEBP인지 확인, 저장 이름은 UUID |
| `job/` | 보호 작업. 기록을 PROCESSING으로 먼저 저장 → AI 호출 → DONE 또는 FAILED(이유) |
| `ai/AiClient` | AI 서버 `POST /protect` 호출. 최대 5분 기다림. AI 서버 오류를 사람이 읽을 말로 바꿈 |
| `common/` | 모든 오류를 `{"error": "메시지"}`로 통일 |
| `application.properties` | 포트 8080, AI 서버 주소, 저장 위치, 업로드 20MB, `server.address=127.0.0.1` |

- Spring Boot 4.1.2, Java 17, Maven(`mvnw` 포함), H2 파일 DB, springdoc(Swagger UI)
- 실행 방법: `backend/README.md`

### API
| 요청 | 하는 일 |
|---|---|
| `POST /api/images` | 사진 올리기 → 사진 번호 |
| `POST /api/protection-jobs` `{"imageId": 1}` | 보호 작업 만들기 (AI 처리까지 기다림) |
| `GET /api/protection-jobs/{id}` | 작업 상태와 결과 사진 주소 |
| `GET /api/images/{id}` | 사진 파일 (원본 또는 보호된 사진) |

시험 화면: http://localhost:8080/swagger-ui.html

### DB 표
| 표 | 내용 |
|---|---|
| `image` | 사진 번호, 원본/보호 구분, 파일 이름, 형식, 크기, 저장 이름, 만든 시각 |
| `protection_job` | 작업 번호, 원본 사진, 보호된 사진, 상태, 실패 이유, AI 처리 시간, 시작·끝 시각 |

### 트러블슈팅
| 문제 | 원인 | 해결 |
|---|---|---|
| 프로젝트 생성 사이트가 Gradle 프로젝트에서 500 오류 | 사이트 쪽 오류 | Maven 프로젝트로 받음 (`mvnw` 포함이라 설치 불필요) |
| `spring-boot-starter-parent:4.1.2.RELEASE`를 찾을 수 없음 | 사이트의 버전 표기와 실제 배포 이름이 다름 | `4.1.2`로 고침 |
| 같은 와이파이의 다른 기기에서 사진을 내려받을 수 있음 | Spring Boot는 기본으로 모든 네트워크에서 접속을 받음, 로그인 없음 | `server.address=127.0.0.1` |

## 결과
**정상 흐름 (person_a_1.jpg)**
1. 사진 올리기 → 201, 사진 1번
2. 보호 작업 → 201, DONE, 보호된 사진 2번 (AI 38.5초, 요청 전체 38.7초)
3. 사진 2번 내려받기 → `person_a_1_protected.png` 1016×1354, Week 9 AI 서버 직접 호출 결과와 바이트까지 같음
4. Swagger 화면에서 보호 작업 실행 → DONE (40.4초)

**오류**
| 상황 | 결과 |
|---|---|
| 사진이 아닌 파일 | 415 "JPEG, PNG, WEBP 사진만 올릴 수 있습니다" |
| 파일 없이 업로드 | 400 |
| 21MB 파일 | 413 "파일이 너무 큽니다" |
| 얼굴 없는 사진 | 작업 FAILED, "얼굴을 찾지 못했습니다" |
| AI 서버 꺼짐 | 작업 FAILED, "AI 서버에 연결할 수 없거나 응답이 너무 늦습니다" |
| 없는 사진·작업 번호 | 404 |
| 사진 번호 빠짐 | 400 |
| 보호된 사진을 다시 보호 | 400 |

- 와이파이 주소로는 접속되지 않음 (내 Mac에서만 동작)
- 자동 테스트(`./mvnw test`) 통과

## 한계
- 보호 작업 요청이 40 ~ 90초 동안 기다린다. 그동안 다른 작업도 줄을 선다(AI 서버가 한 장씩 처리).
- 로그인이 없고 사진 번호가 1, 2, 3…이라 추측하기 쉽다. 지금은 내 Mac에서만 접속되게 막아 두었다.
- DB 비밀번호가 없다(개발용 H2). 배포 때는 진짜 DB 서버와 비밀번호(환경 변수)가 필요하다.
- 업로드한 원본 사진을 지우는 기능이 없다. 얼굴 사진이라 보관 기간과 삭제를 정해야 한다.

## 깨달은 점
- 백엔드는 AI 서버를 믿지 않고 먼저 걸러야 한다. 사진 형식과 크기를 미리 확인하면 무거운 AI 서버까지 가지 않는다.
- 실패도 기록이다. AI 서버가 꺼졌거나 얼굴이 없을 때 작업을 FAILED로 남기고 이유를 적어 두면, 사용자에게 무엇이 잘못됐는지 알려 줄 수 있다.
- 기본 설정이 안전하다고 가정하면 안 된다. 서버는 기본으로 네트워크 전체에 열린다.

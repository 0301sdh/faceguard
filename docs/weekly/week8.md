# Week 8 — 사진 전체 보호와 처리 속도 (서비스 준비)

> **결론: 방식 C'로 결정.** 사진을 긴 변 1024까지만 줄인 뒤, 얼굴에 노이즈를 넣고 사진 전체에 되돌려 붙인다. 사진 전체 기준으로 FaceID 생성 ArcFace 0.140(성공), SimSwap -0.034(성공)이다. 사진 1장에 약 13초(T4)가 걸린다. 사진을 그대로 쓰면(방식 A) 효과가 약해지는 원인은 끝내 찾지 못했고, 한계로 기록한다.

## 목표
지금까지는 잘라낸 224×224 얼굴로 실험했다. 실제 서비스처럼 **사진 전체**를 받아 보호된 사진 전체를 돌려줄 때도 효과가 유지되는지 확인하고, 처리 시간을 잰다.

## 방법
- 노이즈 설정은 Week 7 ensemble과 같다 (SimSwap ArcFace + FaceID ArcFace, eps 5/255, EOT 변형 4개, steps 30, 노이즈 seed 0).
- 사진 전체 처리 순서: 얼굴 찾기 → SimSwap 방식으로 224 crop → 노이즈 만들기 → 노이즈만 원래 사진 좌표로 되돌려 붙이기 (`protect_full`)
- 평가는 보호된 **사진 전체**를 그대로 SimSwap과 FaceID에 넣고, 결과를 원래 크기의 내 사진과 비교한다.
- 노트북: `notebooks/simswap_robustness.ipynb`(노이즈, SimSwap), `notebooks/ipadapter_faceid_eval.ipynb`(FaceID 생성)

| 방식 | 내용 |
|---|---|
| A | 원래 사진 그대로 보호 |
| B | A + FaceID 쪽 loss를 실제 경로(사진 전체 → 112)로 계산 |
| C | 얼굴이 224 crop 크기가 되도록 사진 전체를 먼저 줄인 뒤 A |
| C' | C처럼 줄이되, 긴 변이 1024보다 작아지지 않게 멈춤 |

## 결과
결과 vs 내 사진, 사진 4장 평균이다. 낮을수록 보호가 잘 된 것이다.

| 방식 | 사진 크기 | SimSwap: ArcFace | FaceID 입력: ArcFace | FaceID 생성: ArcFace | FaceID 생성: FaceNet |
|---|---|---|---|---|---|
| 보호 안 함 | 원래 | - | - | 0.748 (실패) | 0.812 (실패) |
| 잘라낸 얼굴 (Week 7) | 224 | -0.025 | - | 0.062 (성공) | 0.438 (부분) |
| A | 원래 | -0.032 | 0.191 | 0.198 (성공) | 0.587 (부분) |
| B | 원래 | -0.034 | 0.153 | 0.263 (부분) | 0.562 (부분) |
| C | 208 ~ 1354 | -0.065 | 0.019 | **0.080** (성공) | **0.487** (부분) |
| **C'** | **683 ~ 1354** | -0.034 | 0.097 | **0.140** (성공) | 0.533 (부분) |

- 보호 안 한 사진은 줄여도 그대로다 (C 0.729, C' 0.727). 좋아진 것은 노이즈 덕분이다.
- C'에서 사진별 FaceID 생성 ArcFace: a_1 -0.001, a_2 0.054, a_3 0.253(부분), a_4 0.256(부분)
- 화질(얼굴 영역 PSNR) 37.1 ~ 37.9dB로 모든 방식이 같다.
- 처리 시간(T4): 사진 1장 약 13 ~ 15초. 그중 노이즈 계산이 약 13초이고, 얼굴 찾기·줄이기·붙이기는 합쳐 1초 미만이다.
- 눈으로: 방식 A도 "내가 아님"이지만 약간 닮은 느낌이 남았다.

## 원인 찾기 (미해결)
| 가설 | 확인 방법 | 결과 |
|---|---|---|
| FaceID는 사진 전체에서 따로 얼굴을 자른다 | 방식 B: 그 경로를 loss에 넣음 | 개선 없음 |
| 224 노이즈를 늘려 붙이면 뭉개진다 | 방식 C: 늘리지 않게 사진을 줄임 | 효과가 돌아옴. 하지만 아래 진단에서 노이즈는 A에서도 거의 그대로 전달됨 |
| 보호 사진에서 얼굴 위치가 어긋난다 | 진단: 원본 정렬 vs 다시 찾은 정렬 | 어긋남 0.1 ~ 1.7px(EOT 범위 안), 노이즈 전달률 A와 C 비슷(0.55 ~ 0.97) |

- 노이즈 무늬는 A에서도 모델에 잘 전달되는데 효과는 약하다. 차이는 FaceID 쪽에서만 난다.
- 남은 의심: 큰 사진을 112로 한 번에 줄일 때 생기는 **바탕 얼굴 그림의 차이**. 공격할 때는 224를 거쳐 112로 두 번 줄인다. 확인하지 않았다.

## 결정: 방식 C'
- 4장 평균이 성공선(0.222) 안이고, SimSwap 보호도 유지된다.
- 사진이 너무 작아지지 않는다 (C는 a_4가 312×208까지 줄어 SNS용으로 부적합).
- C 수준의 효과와 원래 해상도를 함께 얻는 방법은 원인을 찾은 뒤에 다시 시도한다.

## 한계
- a_3, a_4는 FaceID ArcFace 기준 부분 보호다 (0.253, 0.256).
- FaceNet 흔적이 잘라낸 얼굴(0.438)보다 더 남는다 (0.533).
- 돌려주는 사진이 최대 긴 변 1024 수준으로 작아질 수 있다.
- 사진을 그대로 쓰면 효과가 약해지는 원인을 찾지 못했다.
- 방식 D(노이즈를 얼굴 실제 크기에서 만들기)는 시험하지 않았다. 효과가 있는지 없는지 모른다.
- 노이즈 seed 1개, 사진 4장, 본인 1명의 결과다. 처리 시간은 Colab T4 기준이다.
- FaceID 생성 이미지는 Drive `week7/w8_*` 폴더에 저장했다 (Week 7 생성 함수를 그대로 써서).

## 깨달은 점
- 잘라낸 얼굴에서 통한 노이즈가 사진 전체에서도 같은 효과를 낸다는 보장은 없다. 서비스와 같은 입력으로 평가해야 한다.
- 그럴듯한 설명도 직접 재 보기 전에는 가설이다. 진단 한 번으로, 그럴듯했던 설명 두 개가 원인을 충분히 설명하지 못한다는 것을 알았다.
- 원인을 다 몰라도 서비스에 쓸 방법은 정할 수 있다. 무엇을 모르는지는 한계로 남긴다.
